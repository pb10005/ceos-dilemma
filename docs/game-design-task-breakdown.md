# ゲームデザイン改善 タスク分解（MVP後）

## 目的
- 学習体験（因果理解）とリプレイ性を高める。
- 実装コストを抑えつつ、プレイ満足度に直結する改善から着手する。

## 優先順位（高→低）
1. 意思決定の因果フィードバック可視化
2. ゲームオーバー時の再挑戦ガイド
3. イベント予兆の追加
4. マルチ評価スコア導入
5. 戦略アーキタイプ分岐

---

## Sprint 1（1〜2週間）: 因果可視化 + 再挑戦導線

### A. 意思決定の因果フィードバック可視化
- [ ] A-1: `types/` に「ターン寄与ログ」型を追加
- [ ] A-2: `lib/gameEngine.ts` の `processTurn` が寄与ログを返すよう拡張
- [ ] A-3: `components/Dashboard.tsx` に「今ターンの変化要因」表示を追加
- [ ] A-4: `components/KPIBoard.tsx` に主要寄与Top3表示を追加
- [ ] A-5: `tests/gameEngine.test.mjs` に寄与ログ生成テスト追加

完了条件:
- 意思決定ごとの寄与が最低3指標（売上/現金/在庫）で可視化される。
- 既存テスト + 新規テストが通る。

### B. ゲームオーバー時の再挑戦ガイド
- [ ] B-1: 倒産原因タグ（流動性不足/過剰在庫/過剰負債など）を `processTurn` 返却に追加
- [ ] B-2: `data/lessons.json` を新設し、原因タグごとの改善提案を定義
- [ ] B-3: `components/Dashboard.tsx` にゲームオーバー提案UIを追加
- [ ] B-4: `tests/gameEngine.test.mjs` に原因タグ判定テストを追加

完了条件:
- ゲームオーバー時に原因タグと改善提案が表示される。

## Sprint 2（1〜2週間）: イベント予兆 + 評価スコア

### C. イベント予兆追加

- [ ] C-4: 予兆と実イベントの整合性テストを追加

### D. マルチ評価スコア導入
